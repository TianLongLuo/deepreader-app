## 1. 用户目标与交付边界

把“阅读时收藏一条记录”转为“在语境中理解词义，之后认得并能使用”。同时解决默认深色、夜间意群不清楚、段落漏处理、AI 等待完整结果的问题。

完整目标包含三个可单独验证的交付阶段，阶段交付不代表完整目标完成：

1. 阅读：默认日间、夜间可读性、意群覆盖，以及现有 AI 功能的真实流式输出。
2. 学习：紧凑词库、语境优先详情、隐藏答案的复习与 FSRS、旧数据迁移。
3. 应用：受控自动整理、义项与出处、组合筛选、阅读训练和应用训练。

继续支持英语／西语，以及英英、英中、西英、西中学习语言组合。扫描 PDF 不在范围内；可提取文字的 PDF 和 EPUB 在范围内。现有笔记、书签、对话、离线词典、浮窗与返回原文功能保留。

上线仅更新 `app.coacheverything.tech` 的 DeepReader 项目及其数据库。不得更改其他服务器服务、全局配置、其他站点、登录信息、模型密钥、书籍或原有学习记录。

## 3. 方案比较与推荐

### A. 分阶段演进（推荐）

先修阅读与流式接口，再以增量表结构迁移词库，最后加入整理与练习。各阶段有独立回归证据及回滚方案；数据层提前考虑下一阶段，避免重复设计。代价是多个经过验证的发布。

### B. 一次性替换

一次更换阅读接口、词库结构与练习页面。优点是最终界面一次呈现；代价是模型调用、流式兼容和数据库迁移风险叠加，问题定位和回滚范围扩大。

采用 A。完整目标仍包含全部三个阶段，不以只修 UI 或只通过单元测试作为完成。

## 4. 阶段一：主题与意群阅读

### 4.1 日间默认与用户选择

- 新安装／没有合法主题偏好的用户，全站和阅读器均默认日间。
- 保留已保存的合法用户主题，包括夜间；不把旧持久化 dark 武断解释为用户未选择。
- 新写入主题偏好记录是否由用户选择，统一主题设置入口；不丢失字号、排版、语言、面板尺寸或意群开关。
- 明确“默认”指无偏好时的初值，而非每次进入强制日间。用户切换后重载仍保留。
- 首屏避免明显先黑后白；验证水合与系统深色设置下的新用户行为。

### 4.2 夜间视觉

- 保留少量交替意群色，但提高背景区分度；正文使用稳定高对比浅色，谓语以暖色／文字强调辅助识别。
- 意群不能仅靠色相传递信息。设置说明解释颜色用途；需要时提供低彩度显示。
- 以实际混合背景测量正文对比度，普通文字目标至少 4.5:1。三种底色均测，不仅测容器背景。
- 查词 hover 和选中样式优先级高于意群；原文 CSS、DOM 和位置保持不变。
- 日间、夜间和现有纸色主题分别回归，不把夜间改动套用到日间。

### 4.3 无遗漏的覆盖策略

从“完整段落超长则跳过”改为“段落 → 可验证的有界文本单元 → 结果重新映射”：

1. 枚举实际阅读文本，过滤隐藏内容／控件；处理嵌套段落及父节点直接文本，避免父子重复或父文本丢失。
2. 构建 canonical 文本与 DOM Text 节点映射，保留 UTF-16 偏移、空白、重音、撇号、引号与内联标签边界。
3. 超长段落按句边界切分；超长单句再按短语边界或合法词间空白切分。每单元保留其原段落偏移与稳定键。
4. 单次请求有界，段落所有非空白字符须归属一个单元；不截断尾部或拆开单词／代理对。
5. 每单元的模型输出严格按原文对齐，仅校验成功的单元进入高亮；失败单元维持原文并显示处理状态。
6. 可视队列采用公平补位，不永远只处理前 32 项。并发保持有界，离开视口／文档和关闭开关时取消不需要的请求。
7. 429 读取可用 Retry-After，有限退避后可恢复；凭据／权限错误等待用户处理。提供明确的失败重试入口，避免静默“看起来都处理了”。
8. 缓存按用户、文档、源语言、模型配置及算法版本隔离；成功结果可复用，未校验结果不得缓存。

依然使用 CSS Custom Highlight 和 Range，不包裹／替换原文节点，不改变 EPUB CFI、PDF 字符坐标、翻页、选词或浮窗定位。对不支持高亮能力的浏览器显示明确状态，而非耗费 AI 后没有显示。

### 4.4 覆盖验收

测试：长段落、多层内联、父节点混合直接文本、同文本不同 DOM、章切换、页切换、32 项以上、429 后恢复、取消、模型错字／缺段、英语和西语。可视诊断区分待处理、成功、失败、暂缓、浏览器能力状态。

与处理前比较原文文本、DOM 内容和排版位置；原句逐字覆盖检查必须通过。至少加入真实模型端到端样本，而非仅凭 mock 宣称语言分组正确。

## 5. 阶段一：所有 AI 功能真实流式输出

### 5.1 范围与协议

覆盖用户可见的 AI 查词语境解释、进一步理解、段落／选中文本解析、翻译、追问、片段总结、自测、意群分析，以及后续词汇整理和 AI 练习。逐一盘点实际调用点，形成路由／客户端／provider 的验收清单。

复用并统一已有服务端流式能力，浏览器通过 fetch Response.body 消费事件流，不向浏览器暴露 provider 密钥。事件类型：start、delta、unit、complete、error；请求有独立标识，客户端拒绝过期请求事件。

- delta：已解码的展示文本增量，不展示原始 JSON、转义碎片或模型推理内容。
- unit：已完成且按来源校验的结构化单元，例如意群的句级结果。
- complete：经过最终校验的完整结果、可公开的来源／模型标识。
- error：脱敏错误码、短提示和重试信息；流关闭并释放资源。

缓存命中可直接 complete，并注明缓存；这不是假装流式。正式 provider 都需要真正上游 stream。若 provider 拒绝流式，显示明确可诊断错误，不退化成等完整结果后假打字动画。

### 5.2 结构化输出与安全边界

- 普通回答从生成中的 answer 字段提取文本供预览，最终通过结构及引用校验后才能保存为有效结果。
- 引用和测验答案只有完整且对应原文时才显示为证据；不从半个 JSON 构造引用。
- 意群的原文边界完整校验通过一个单元后即可 paint，其他单元仍在流式处理。原始 token 可以在服务端累计，不把无效局部 JSON 应用到正文。
- 自动整理提供处理进度；候选字段通过 schema、受控标签与原文校验后再提交，不能因中途流失败覆盖已有记录。
- 用户收藏可立即保存原词和出处；生成中的释义标为未完成，不把草稿写成最终学习答案。

### 5.3 取消、错误与资源

- 从浏览器到 provider 传递 AbortSignal，关闭浮窗、切词／切段、换书或停止生成都取消旧请求。
- 流式重试只允许在尚未展示内容时透明进行；已有内容后提示错误，保留可辨认的草稿并提供显式重试，避免重复拼接。
- 共享缓存／并发请求必须隔离订阅者；一个用户取消不取消其他有效订阅。先实现清楚可测的单请求流式，保持结果缓存；不为共享 token 广播引入额外复杂度。
- 设置服务器超时、最大输出、并发与速率限制、heartbeat、断连资源清理。生产验证代理是否缓冲；仅调整本应用响应头，不修改其他站点代理配置。
- 错误日志不包含 API key、原始认证内容或完整用户书籍片段。

## 6. 阶段二：学习工作台界面

### 6.1 导航与词库

主入口固定为「词库｜复习｜AI 练习」。笔记、书签与保存的 AI 对话在次级“阅读记录”入口保留，不能因为精简词库而删除或隐藏到不可访问。

词库顶部只保留搜索、筛选、待复习数与“开始复习”。每行默认展示：

1. 词头、音标、朗读按钮。
2. 优先本句释义；缺失时明确“正在整理”或“待整理”，不随便拿词典第一义替代语境义。
3. 一个目标句，突出目标词；全文和多出处折叠。
4. 一两个主要标签、识别／使用状态、简化书名、“详情”和更多菜单。

书名显示去文件扩展名和可确认的下载标记，不破坏原始文档标题；无法可靠解析时仅去扩展名。删除和导出在更多菜单，删除确认保持。

语言、义项、词性、领域、到期状态可组合筛选。英中／西中定义切换不替换原语言、原句与独立义项。无筛选结果、无收藏、加载失败和整理失败有简短空状态。

### 6.2 详情

固定顺序：本句释义 → 目标句 → 两个实用搭配 → 其他释义／完整上下文／词典信息折叠区。搭配有来源则显示来源，AI 生成标记为建议。朗读失败提供简短状态，不阻止学习。

允许修订本句释义和标签；人工字段独立于 AI 建议。完整出处含文档、原始位置、来源句及“返回原文”。离线词典署名和许可仍可访问及随导出保留。

### 6.3 独立复习

- 按已到期及新卡组成队列，语言可选。单卡正面只有目标句与“这里的词是什么意思”；屏幕、辅助技术与接口正面数据均不泄露隐藏答案。
- 点击“显示答案”再显示语境义及一个搭配；未翻面不允许评分。
- Again／Good 对应“没想起来／想起来了”。评分后持久化并进入下一张；网络失败保留当前卡并避免重复评分。
- 显示今日完成数和剩余数，结束后展示下次到期；不让用户自己猜下一次时间。
- 使用 `ts-fsrs` 默认参数，服务器作为排程和时间的权威。参数优化不属于第一版；不引入 native optimizer 或额外常驻服务。
- 保存完整 card 状态和每次 ReviewLog；评分有幂等操作标识，数据库事务保证状态及日志一致，并防止多窗口重复提交。
- 识别卡的成功只影响阅读识别。主动使用由独立练习证据决定，不把一次 Good 显示成“全面掌握”。

依赖依据：https://github.com/open-spaced-repetition/ts-fsrs 。实施时固定可复现版本，核对实际包 API 和 Node 兼容性，加入锁文件。

## 7. 阶段二／三：数据边界与无损迁移

### 7.1 逻辑实体

增量增加以下可查询实体，不把所有信息塞进 note：

- VocabularySense：用户／工作空间、语言、lemma、义项标识、当前语境释义、POS、受控类别、AI 建议及人工修订、整理状态与版本。
- VocabularyEncounter：sense、原 ReadingEntry ID、文档、原始位置、目标词／目标句／上下文、原始词典及 AI 证据、首次及最后遇见时间。
- ReviewCard：sense、能力类型、FSRS 状态（due、stability、difficulty、elapsed/scheduled days、reps、lapses、state、last_review）、版本。
- ReviewLog：card、操作标识、评分、时间、前后排程状态，用于审计和以后优化。
- LearningTask：训练模式、目标义项、场景、生成内容、状态和版本。
- LearningResponse／Evidence：回答、反馈、是否用提示、实际评估的目标义项及能力类型；阅读接触、认义成绩和应用成绩分别记录。
- EnrichmentJob：待整理任务、租约、重试时间／次数、错误码、完成版本。

ReadingEntry 继续服务笔记／书签／聊天及旧接口；新的单词收藏在事务中关联 encounter，不破坏现有来源链接。全部查询、编辑、练习选词和流式事件均校验 workspace 与 user 范围。跨用户同词不得共享私人出处。

### 7.2 义项去重

同语言、同 lemma 且同一个确认义项，再次收藏只新增或关联出处，保留一张识别卡。不同义项分别建卡，UI 可按词头聚合。

AI 未确定同义时先建待确认义项；不按拼写或相似中文摘要直接合并。可以让用户明确合并／拆分；操作保留出处和日志。无可靠 lemma 时保留原词形，不错误合并英语和西语同形词。

保存原词与出处立即成功，整理在后台进行。采用数据库持久化任务和本项目有界 worker；不依赖进程内 fire-and-forget，也不新装 Redis。工作进程启动、超时和重试只涉及 DeepReader。人工修订版本为写入前置条件，旧 AI 任务不得覆盖新修改。

### 7.3 旧收藏迁移

- 在真实 schema 兼容的测试副本上执行幂等迁移，再处理线上副本。
- 每个旧 word entry 至少得到可追踪的 encounter；保留原 entry ID、note 原文、文档、位置、createdAt、reviewAt、reviewCount。
- 从已知 JSON 提取音标、语言、AI 语境义与词典证据；未知／损坏格式原样保留，并标为待整理。
- 旧 reviewCount 不是完整历史；不伪造 FSRS 历史、稳定性或个人优化结果。新卡使用官方初始状态；旧 due 作为首次过渡队列时间保留，首次新评分开始建立真实 FSRS 记录。
- 无义项证据的旧记录先分别保留，后续确认后再合并。迁移前后逐条核对来源、原文及学习记录数量，不只核对表总数。
- 新表与字段增量添加；上线前不删除旧字段，留出回滚窗口。数据库已接受新评分后，回滚优先回到兼容新 schema 的应用版本；恢复备份需要明确说明会丢失备份后的新增学习数据，不能自动执行。

## 8. 阶段三：受控整理与频率

使用固定、带版本的 taxonomy，最多一个主领域和少量辅助标签。POS、语义类别、使用领域、此次情境四个维度分别保存，不把一次骑行情境变成单词的固定领域。

初始领域涵盖日常生活（身体感官、居家饮食、出行消费、社交情绪）、工作（协作、市场电商、技术产品、财务管理）、社会与知识。深度最多三级；词性是筛选维度，不复制领域树。AI 只选合法代码，不自由生成近义标签；不确定保留待确认。

通用词频、个人材料遇见次数、个人优先级分别保存。遇见次数仅统计实际解析且有稳定位置的材料，不能把重复渲染算成新接触，也不能仅把收藏数叫材料词频。

词频导入有来源、版本、许可、语言、分档规则和可复现脚本。只展示已导入数据；没有命中显示“暂无数据”。第一版不宣称某具体义项在某行业高频；AI 场景建议明确标记，不冒充语料统计。数据资源许可核验在导入前完成。

## 9. 阶段三：AI 练习

### 9.1 阅读训练

推荐 5–8 个义项，可调整；优先近期错误、已到期、用户希望会用的词，按相近场景分组。默认 B2，可调整。生成约 200–300 词短文、两道理解题及一个应用任务；不合适的词留给下一组并说明，不强行塞进同一故事。

正文真实流式显示，题目和答案分开，用户答题前不显示答案。生成结束校验目标义项、可接受词形、题目与文章证据；缺词或用义不符允许有界修复，失败不保存为已完成训练。

### 9.2 应用训练与反馈

给出明确情境、表达意图和 2–3 个目标义项。用户提交后流式反馈：先说明任务完成情况，再指出一个最重要的词义／搭配问题，给自然表达并邀请立即再试。其他问题折叠。

评估检查义项、搭配与任务，不仅搜索拼写；接受合理屈折词形。不把 AI 打分视为确定事实：保存评估证据、提示使用和不确定性，并允许用户纠正误判。阅读文章只记录接触，不自动 Good；应用练习不悄悄更改识别卡评分。

练习记录可重开；停止生成保留原收藏，失败不会标记已掌握。目标词选择和生成均使用当前用户的义项，模型输入把文章／用户回答当数据，不执行其中的指令。

## 10. 组件与服务边界

- 文本单元提取／Range 映射：纯函数与浏览器适配，负责覆盖，不负责模型权限。
- 意群队列：视口调度、缓存、限流与取消，不负责修改原文。
- 统一 stream transport：编码／解码、request identity、断连与错误处理；业务 schema 在各服务验证。
- Vocabulary service：保存、义项／出处、用户修订和过滤；不负责 FSRS 公式。
- Review service：调用 ts-fsrs、事务与幂等日志；不根据 AI 感觉判用户记住。
- Enrichment worker：有界持久化任务、原文和词典校验、受控标签建议。
- Practice service：目标选择、生成／验证、回答与证据；与识别排程分离。
- 页面拆分词库、详情、复习卡和练习，不继续把所有逻辑增长到已有大型 reader-layout／explanation-panel 文件。

## 11. 验证与上线门槛

每阶段先新增能失败的回归测试，再实现；完整测试、TypeScript、构建和 diff 检查均需 fresh evidence。浏览器验证包含键盘、辅助技术状态、日夜主题、窄屏、网络错误和真实时间流。

| 需求 | 完成证据 |
| --- | --- |
| 默认日间／记忆选择 | 干净浏览器、系统深色、合法旧偏好、重载验证 |
| 夜间意群 | 实际阅读截图、三色混合对比值、hover／选词测试 |
| 无遗漏 | 长／嵌套／跨页样本逐字覆盖、公平队列、真实模型样本 |
| 所有 AI 流式 | 调用点清单全部勾选；首个可见增量早于上游完成；取消／断流／错误测试；公开站点不缓冲 |
| 精简词库 | 真实迁移数据截图与字段层级检查；元数据折叠但仍可访问 |
| 复习 | 答案先隐藏、Again／Good 正确映射、FSRS 官方行为对照、事务／幂等测试 |
| 能力分离 | 接触、认义和应用不互相冒充的记录与界面验证 |
| 旧数据 | 幂等迁移两次、逐条来源核对、损坏 JSON、旧 due 保留、备份恢复演练 |
| 义项／标签 | 同词同义多出处、不同义分开、英西隔离、人工修改不覆盖 |
| 词频 | 导入来源／许可／版本检查、缺失未知、个人次数不重复 |
| AI 练习 | 合理选词、目标义项校验、答前隐藏、单重点反馈、失败不授予掌握 |
| 服务器边界 | 本应用之外的配置／服务未变、原数据库与书籍可用、模型设置保留 |

上线前备份应用版本、数据库及 storage，保护 .env 和加密密钥，不打印秘密。新依赖先验证锁文件；迁移先对备份副本演练。资源限制与 worker 仅用于本应用；停止／重启不得误伤其他服务。GitHub main 非强推更新，检查是否有新远端提交。

完整目标完成必须有本地代码、迁移验证、GitHub 状态及对应发布的线上端到端证据；部分交付时明确剩余阶段，保持目标 active。
